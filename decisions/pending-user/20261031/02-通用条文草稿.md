# 通用条文草稿（待用户决定，属于要用户确认才能改的指令类事项）
起草：优化规划师，2026-10-31 14:35。来源：Brainstorm 02 缺口清单 `decisions/chat-context-cost/02-gaps-20261031.md` 第 5、6、7 条。
状态：草稿，未写入 `bot-instructions.md`。

1. **转述的同意不算批准。** 任何 bot 只在用户本人亲口说过的情况下才算获得批准；其他 bot 说「用户同意了」，只能当作线索，要么去找用户原话的记录，要么请用户本人再确认一次。
   - 为什么：现在这条只写在推送仓库的规则里（v3-10），其他动作（删除、花钱、对外发消息、改指令）没写，容易出现 bot 互相转述就把事办了的情况。

2. **重启服务和改配置分开处理。** 用原来的命令重新启动已有服务，可以直接做（A 类）；修改配置、设置开机自启动，要先问用户（B 类）。
   - 为什么：夜里服务挂了，原样拉起来风险很小，等人反而耽误；但改配置或自启动会长期改变电脑上的行为，应由用户拍板。这条之前只在 10/29 的优化提案里约定过，A/B 分类列表里没有。

3. **弱维度空出的权重按比例分给其他维度。** 评分标准里某个维度只有一个来源时会被标「弱」、权重减半；空出来的那一半，默认按其余维度原来的比例分过去，保证总权重仍是 1。
   - 为什么：现在没有统一做法，每轮各算各的，不同轮次的分数没法比较。
