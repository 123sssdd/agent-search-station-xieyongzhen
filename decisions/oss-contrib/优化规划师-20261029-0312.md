# 优化规划师意见：开源贡献流程（流程与额度角度）
1. 问题：每轮都走「管家→01→Searcher→质量评估」四跳，太长。方案：只在首次建立候选池时走全流程（B 档）；之后补充候选由管家直接用 gh search 增量补（C 档，≤30 分钟，不派 Searcher）。成本低，风险是候选质量略降，影响是额度省一半以上。推荐采用。
2. 问题：Exa 额度不可控。方案：只在 gh search 候选数 <10 时启用 Exa，每轮≤20 次调用，用量记入 eval（对齐 v3-18）。推荐采用。
3. 问题：候选会被反复评估。方案：评分结果缓存 30 天（同搜索方案的标准缓存），已评过的仓库跳过，只复查 issue 是否仍开放。推荐采用。
4. 问题：认领后容易卡住。方案：状态「已认领」超过 7 天没有进展，例会时自动标为阻塞，由管家决定续做还是放弃。推荐采用。
5. 问题：Notion 写入有两种做法。方案：维持 Memory 独写，管家只给条目（落盘 rounds/），不授权管家直写，避免多个写入方。推荐采用，若用户要直写属 B 类。
6. 补充：模板默认值里加「每周最多认领 1–2 个 issue」，避免并行过多。
