# 开源贡献流程｜会议定稿（01，03:15）
来源：01-meeting-20261029-0310.md（01/02/优化规划师/Memory/Github 管家意见）。用户原话经 Github 管家转达（03:10、03:12）。

## 分工与交接
1. **Github 管家**写搜索方案：decisions/oss-contrib/plan-YYYYMMDD-HHMM.md → 交 01（或当值 BrainStorm）。
2. **当值 BrainStorm**定档位：首轮建池用 B 档，之后的增量用 C 档，由管家直接只读跑 gh search；B 档以上派 Searcher → 质量评估打分 → 非开轮 BrainStorm 复核 → 结果写 rounds/oss-YYYYMMDD-HHMM.md 并回传管家。
3. **Github 管家**排优先级、管进度，维护本地 oss-contrib/registry.json，并向用户汇报。
4. **Memory**按 issue_key 把 registry 单向 upsert 到 Notion（Memory 独写）。
5. **Copilot bot**写代码；用户把自己的提交和 PR 告诉管家，由管家记录进度。

## 搜索方案模板
目标、领域、语言、star 区间（默认 1k–10k）、更新时间、License 白名单、good-first-issues>=3（help wanted 兜底，v3-21）、维护活跃度、CLA 要求、是否已被认领、排除项、建议档位、截止时间。
Exa 只在候选 <10 时用，每轮 ≤20 次（v3-18）。评分缓存 30 天。

## Notion「开源项目贡献管理」（建在学习中枢 hub 下）
字段：
- 标题：issue_key（去重用）
- 项目信息：项目名、仓库链接、语言、Stars 及记录日、License、CLA 要求
- issue 信息：Issue 链接、类型（bug/feature/docs）
- 状态（原生 status）：候选 / 已认领 / 开发中 / PR 已提 / 等待维护者 / 已合并 / 放弃
- 跟进：优先级 P0–P2、负责人、开始日、合并日、最后活动日
- 产出：PR 链接、面试素材（问题–方案–影响）
- 关联：需用户确认草稿、关联轮次、关联 Todos、备注

流程：先建空库 → 回读 schema → 管家核对 → 导入数据。

## 规则
- **阻塞**：已认领 7 天无进展标为阻塞，14 天无进展由管家建议放弃（两档统一）。
- **认领上限**：每周 1–2 个。
- **例会汇报**：管家固定议程 ≤5 行，内容为新增候选、认领 / 在做 / PR / 合并、阻塞、下周计划。
- **A 类**：本地克隆、本地测试。
- **B 类，需用户确认草稿**：fork、push、开 PR、评论、发 issue、签 CLA。fork 维持 B 类。
