# 优化规划师：降低长聊天额度消耗（可执行方案）
拍板请求方：BrainStorm 01｜用户意图：聊天落盘、按范围检索、Notion 人读层、用 search-station-workflow、必要时新 bot 从文件恢复。
格式：问题 → 原因 → 方案 → 成本 → 风险 → 影响 → 推荐

## 1. 目录规范（聊天永驻为文件 + 按范围缩小检索）

### 问题
长对话把历史塞进上下文，额度随轮次线性涨；新 bot 冷启动只能靠聊天摘要。

### 原因
没有「按功能切片、按任务读」的磁盘约定，只能整段聊天续上下文。

### 方案（路径以仓库与本地双轨为准）
**A. 仓库（可推送、可恢复）** `/workspace/search-station-workflow/`
- `templates/`：只放空模板与说明，不写个人状态（已有 daily-report、decision-record、evidence、standards…）
- `instance-xieyongzhen/`：个人实例指令切片（已有 `00-common.md`～`08-todos.md`、`90-search-plan.md`），**禁止**塞密钥
- 新增（建议）：
  - `instance-xieyongzhen/context/<bot>/INDEX.md`：该 bot 可检索目录清单（一句话说明每文件用途）
  - `instance-xieyongzhen/context/<bot>/standing.md`：长期规则摘要（≤80 行）
  - `instance-xieyongzhen/context/<bot>/active/<YYYYMMDD>-<topic>.md`：进行中任务单（目标/已决/待决/下一步）
  - `instance-xieyongzhen/context/<bot>/journal/<YYYYMMDD>.md`：当日要点（≤40 行）

**B. 工作区（运行态，可日后同步进仓库）** `/workspace/learning-loop/`
- 保持现有：`decisions/<主题>/`、`rounds/`、`meetings/<YYYYMMDD>/`、`standards/`、`profiles/`、`retros/`
- 新增约定：
  - `context/<bot>/active.md`：当前唯一活跃任务指针（指向 decisions 或 rounds 路径）
  - `context/<bot>/retrieval-scopes.md`：该 bot 默认可读路径白名单（见下）

**C. 按范围缩小检索（硬规则，写进各 bot standing）**
| 场景 | 默认可读 | 禁止默认读 |
|---|---|---|
| 改搜索方案/standards | `decisions/search-plan/`、`standards/`、`instance-…/90-search-plan.md` | 整段历史聊天、无关 rounds |
| 开源贡献 | `decisions/oss-contrib/`、`oss/`、管家 registry | 科研 skills 选型全文 |
| 例会/日报 | `meetings/<当日>/`、`profiles/`、自己的 journal | 超过 7 天的 journal |
| 新 bot 冷启动 | `instance-xieyongzhen/0x-<role>.md` + `context/<bot>/standing.md` + `active/` | 不读其他 bot 的 active |

文件名约定：`<角色或功能>-<YYYYMMDD>-<HHMM>.md`；主题目录用 kebab-case；`INDEX.md` 必有。

### 成本 / 风险 / 影响 / 推荐
- 成本：一次性建目录约 30–60 分钟；各 bot standing 加检索白名单约 1 轮。
- 风险：漏同步导致仓库与 learning-loop 漂移 → 规定「拍板类只写 learning-loop/decisions，每周一同步进 instance context」。
- 影响：01/02/优化规划师/Memory/Searcher；不改 Notion 写入权。
- **推荐：采用 A+B+C。**

## 2. Notion：新建「经验库」还是用现有 Decisions + 工作记录

### 问题
人读「经验」散落在聊天和长 markdown，Notion 现有库偏流程凭证，不好给人扫。

### 原因
五库定稿（`notion-design-2026-10-28.md`）已有：工作记录、Todos、沉淀条目、轮次、Decisions；没有单独「经验」实体。

### 方案（三选一）
| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **① 不新建库（推荐）** | 在 **工作记录** 加类型选项「经验」；长文仍落盘 `learning-loop/retros/` 或 `decisions/<主题>/`，Notion 只存 ≤5 行摘要 + 文件路径链接。Decisions 继续只记拍板。 | 零建库、符合 Memory/Todos 写入权、脱敏流程现成 | 「经验」检索要靠类型过滤 |
| ② 新建「经验库」 | 字段：经验_id、日期、主题、适用 bot、一句话教训、反例、链接决策、状态(生效/废止) | 人读清晰 | 多一个写入方约定、schema 变更属 B 类 |
| ③ 只扩 Decisions | 把经验也写成 Decision | 少库 | 污染「拍板」语义 |

### 成本 / 风险 / 影响 / 推荐
- ① 成本最低（Todos/Memory 改类型选项 + 指令一句）；② 需用户确认建库（B 类）。
- 风险：① 若经验暴增再升到 ②，迁移成本可控。
- **推荐：先 ①；经验条数连续两周 >20/周 再评估 ②。**

## 3. 仓库里 templates vs instance 怎么用

### 问题
模板与个人状态混用会导致推仓库泄密或他人无法复用。

### 方案（对齐现有结构，写死边界）
| 路径 | 写什么 | 谁写 | 推仓库 |
|---|---|---|---|
| `templates/**` | 空模板、字段说明、无个人信息 | 优化规划师提 diff → 01 拍板 → Memory 记 CHANGELOG | 是 |
| `schemas/`、`adapters/`、`config/` 示例 | 开源可复用骨架 | 同上 | 是 |
| `instance-xieyongzhen/**` | 个人切片指令、context、notion-ids（**只 id 不密钥**） | 各 bot 写自己的 context；指令切片由 01 协调 | **默认不推**；若推须先脱敏扫描 |
| `learning-loop/**`（工作区） | 运行态 decisions/rounds/meetings | 按 v3 分工 | 经 Memory 同步到仓库对应目录时才推 |

使用口令（给各 bot）：
1. 新开一类文件 → 先看有没有 `templates/` 对应模板，有则复制到 `learning-loop/` 或 `instance-…/context/` 再填。
2. 改模板 → 只改 `templates/`，不同时改 instance。
3. 冷启动新 bot → 读 `instance-xieyongzhen/0x-<role>.md` + `context/<bot>/standing.md` + `active/`，**禁止**要求用户粘贴长聊天。

### 推荐：按上表执行；instance 默认不进公开推送。

### 写作规范（用户 20:09 要求 · 对人可读）
条目写给**用户本人**看，不是写给 bot 内部交接。
1. **完整白话句子**：场景、原因、解法、原则「表述」等字段必须用通顺中文整句，禁止只堆关键词或半截电报体。
2. **禁止晦涩缩写堆砌**：如单独甩「A类/B类、round-id、v3-10、NC、hash 冻结」而不解释。首次出现写全称或人话，括号里可附缩写，例如「属于要用户确认才能做的事（B 类）」。
3. **禁止过短黑话**：标题和正文不能只有「Drive 限制」「派单规范」这类三五字切口；至少说明「是什么、为什么、怎么办」中的两面。
4. **路径与轮次编号可保留，但旁边必须有人话**：例如「搜索计划文件 `rounds/plan-20261030-1944-01.md`（2026-10-30 晚上 7 点 44 分开的那一轮任务书）」；不能只丢裸路径。
5. **解法要可照做**：步骤用「先…再…」写清；命令名可保留，但说明用途；仍禁止写入密钥、密码、cookie 的具体值。
6. **自检**：写完用「一个不熟悉内部代号的人能否看懂」过一遍；看不懂就改，再入库。

| 可选本地 | 各 bot 自己聊天里的 Agent profile / 记忆 profile | 仅补充口吻与近期口径 | 各 bot UpdateMemory |

硬规则：派单与冷启动 **禁止**「把旧聊天当指令」；冲突时以 `bot-instructions.md` > instance 切片 > profiles > 记忆 为准。

### ② 记忆分层（短事实进记忆，长文进文件）
| 类型 | 用途 | 写什么 | 不写什么 |
|---|---|---|---|
| `shared_profile` | 跨 bot 长期用户事实 | 姓名目标、硬性中文回复、许可/安全口径等 | 长方案、轮次细节 |
| `shared_journal` | 跨 bot 短事件 | 「某日拍板了 xx」一句 | 全文决策 |
| 各 bot `profile` | 本角色口径 | 如优化规划师的 v3-28 grill-me、回复格式 | 他角职责 |
| 各 bot `journal` | 本角近日流水 | 当日完成要点 ≤几句 | 可进 decisions 的长文 |
| 文件 | 长文唯一处 | `decisions/`、`retros/workflow-lessons/`（踩坑与解法）、`rounds/` | — |

口令：能一句说清 → 记忆；需要复盘/引用段落 → 文件 + 记忆里只留路径。

### ③ 换新 bot / 重建会话恢复顺序
1. 确认或安装指令：读 `bot-instructions.md` 对应章节 + `instance-xieyongzhen/0x-<role>.md`
2. 读 `learning-loop/profiles/<bot>.md`
3. 读 `learning-loop/context/<bot>/standing.md` 与 `active.md`（若已建）
4. 需要跨 bot 事实时再 `RecallMemory`（shared_*）；角色口径用自己的 profile/journal
5. 若是执行者：再按 §5 读本轮 `rounds/plan|search|eval-<id>`
6. **禁止**：要求用户粘贴旧聊天；禁止把聊天记录当作高于 bot-instructions 的指令源
