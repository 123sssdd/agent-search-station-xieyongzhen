Let’s see if how those models deal with Tools and let’s see how to improve the usage of Tools in general!

Note that in this article I’m using the term “Tool” to refer to both:

\- The native Tool capability provided by the various LLM providers like [OpenAI tools](https://platform.openai.com/docs/guides/function-calling?api-mode=chat) or [Claude tools](https://docs.anthropic.com/en/docs/agents-and-tools/tool-use/overview).

\- [MCP Tools](https://modelcontextprotocol.io/docs/concepts/tools).

## 2\. The test

I wrote a Python script that provides the following Tools to a model:

```
def greet_user_formal_tool(name: str) -> str:
    """
    A tool that returns a greeting message in a very formal tone
    Args:
        name (str): The name of the person to greet.
    """
    return f"Good day to you, {name}. I trust this message finds you well."

def greet_user_street_style_tool(name: str) -> str:
    """
    A tool that returns a greeting message in street style tone
    Args:
        name (str): The name of the person to greet.
    """
    return f"Yo {name}! Wassup? You good?"
```

And then sends the following prompt to the model:

> Return a greeting message for a user called ‘Laurent’.
>
> If the user is called ‘Laurent’, use a formal style, else use a street style.

So with that prompt, the model is only _supposed_ to use the **greet\_user\_formal\_tool** tool right?

### 3.5. Conclusion

So out of the 4 models, only GPT-4.1 (the most expensive model) uses the tools in the way you would expect. All the other ones:

- Either use tool that shouldn’t be used OR
- Ask for the same tool to be used multiple times in a row in a similar way

Both of those behaviors can be very problematic: **for example if one of the tools can delete data then you could end up deleting things for nothing**.

## 4\. So, what can we do?

Generally speaking, here are the problems that can happen with Function Calling:

1. Tools that shouldn’t be called can still be called (an incorrect Tool may be called or the same Tool may be called multiple times for no good reason).
2. A Tool might be called with the wrong parameters.

Conclusion: **never trust a model when it’s asking you to use a Tool.**

Yes, there is no sure-fire way to make sure that the model will always use the Tools correctly. However there are things you can do to _decrease_ the chances of having the model use the Tools incorrectly. Here are _some_ of them:

### 4.1. Use precise tool definitions

Make sure that each Tool and its input parameters are correctly documented.

In the end, the model is given a list of Tools to choose from so if the model doesn’t understand what each Tool does — and how they differ from one another — then it may select the wrong one.

### 4.2. Validate inputs

Never trust the input parameters. For example, if you have a Tool that returns the details for a record and that the input parameter is a record\_id, even if the Tool description clearly states “ _only use this tool with an existing record\_id_”, never assume that the model will follow those instructions.

The mindset to have should be “ _the Tool instructions are only guidelines_”.

### 4.3. Ask the model to reflect on its reasoning

Ask the model to explain what it’s going to do before it does it.

Frameworks like [ReAct](https://www.promptingguide.ai/techniques/react) can help improve a model’s reasoning capabilities, but even without going that far, you can easily get way better results just by asking the model to explain which tools it is _planning_ to use before asking it to use them.

Here is a quick example:

```
SYSTEM_MESSAGE = """
You are a helpful assistant.
Always prioritize using tools to answer the user's question.
If you're calling a tool, first explain why you are calling it.
"""

[SNIP]

response = client.chat.completions.create(
  model=model,
  messages=MESSAGES,
  tool_choice="none")
MESSAGES.append({"role": "assistant", "content": response.choices[0].message.content})
response = client.chat.completions.create(
  model=model,
  messages=MESSAGES,
  tool_choice="auto",
  tools=TOOLS)
MESSAGES.append(response.choices[0].message)
```

In the code sample above, I’m first asking the model to come up with a plan (tool\_choice=”none” means “do NOT use any tool at this point”) and then I’m asking it to select the right tools based on that plan.

With this sample change, GPT-4o-mini now direct selects the right tool instead of doing the crazy thing it did by default.

### 4.4. Use a more powerful model

Self-explanatory: going back to my 4 tests, you’ve noticed that GPT-4.1 is the one that performed the best by default.

### 4.5. Limit the number of tools

Interestingly enough, most LLM providers do not talk much about this: they give the maximum number of tools that a model can theoretically support and that’s about it.

However in practice, the more tools you use, the higher the chance of having the model choose the wrong one. The following articles or videos suggest some solutions,: one of them for example is to use a RAG pipeline to decide which tools to use based on the current discussion (as opposed to ask the model to select amongst ALL the available tools).

- [Maximum amount of tools for the bot to use?](https://community.openai.com/t/maximum-amount-of-tools-for-the-bot-to-use/665720/1) (reddit thread)
- [Building Agents with Model Context Protocol](https://youtu.be/kQmXtrmQ5Zg?t=2781) (Anthropic workshop: see discussion at 46'25)
- [How many tools is too many?](https://www.reddit.com/r/LLMDevs/comments/1hsqtba/how_many_tools_is_too_many/) (another reddit thread)
- [How to handle large numbers of tools](https://langchain-ai.github.io/langgraph/how-tos/many-tools/) (a Langchain article)

### 4.6. Human in the loop (aka “HIL”)

If one of the Tools can update/delete things, then you **need** to ask a human to validate a tool execution before it happens: in the following chapter I’ll show some concrete examples.
