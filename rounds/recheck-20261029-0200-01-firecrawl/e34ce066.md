At the moment I want to explore automatic agentic coding. Thus I did a little research on the current state of the art. I would like to share my findings on the most important benchmark at the moment and interesting open source approaches used on it.

## SWE Bench

Press enter or click to view image in full size

![](https://miro.medium.com/v2/resize:fit:700/1*swC3McOWbd6uZsUCqQmG3g.png)

[https://www.swebench.com](https://www.swebench.com/)

SWE-bench is the go-to benchmark for evaluating coding agents at the moment. The authors took the problems from 2,294 real-world GitHub issues across 12 popular Python repositories, where tests were available. This benchmark tests an agent’s ability to understand and modify existing codebases — not just generate code from scratch. The agents need to coordinate changes across multiple files, functions and classes. The benchmark requires agents to interact with execution environments and handle extremely long contexts, posing a challenge to current models.

## Open-Source Agents used on SWE-Bench

## OpenHands

OpenHands is a framework with connected agents where each agent has prompts and actions. It uses a delegation approach where one agent passes tasks to the next. Most agents can execute Python code with common file functions and terminal commands. OpenHands is moderately easy to install with Docker and is generalistic enough to be used for tasks beyond coding. The authors regularly benchmark their system and provide a plethora of benchmark suites.

- [GitHub](https://github.com/All-Hands-AI/OpenHands) [Paper](https://arxiv.org/abs/2407.16741)
- Best score: 53.00% issues solved
- Main focus: Connected agent architecture with delegation
- Useful for: Various tasks beyond coding

## Aider

Aider is one of the oldest approaches to AI pair programming and remains very popular. It’s quite easy to install via pip and regularly receives new features. This terminal-based tool has a Python API that’s well-suited for automation. The author has conducted extensive research on editing formats for LLMs and has developed a challenging benchmark. Though it has not the best score as it was not tested recently, it is very popular and thoroughly tested.

- [Website](https://aider.chat/) [GitHub](https://github.com/paul-gauthier/aider) [Blogpost](https://aider.chat/2024/06/02/main-swe-bench.html)
- Best score: 26.33% on lite
- Main focus: Simple agent focused on coding by instruction
- Useful for: Terminal-based pair programming with LLMs

## SWE-Agent

SWE-Agent is a multi-purpose agent framework created by the same authors as the SWE-bench benchmark itself. It lets your language model of choice autonomously use tools to fix issues in real GitHub repositories, perform tasks on the web, crack cybersecurity challenges, or handle any custom task. SWE-agent uses configurable agent-computer interfaces (ACIs) to interact with isolated computer environments and employs SWE-ReX for sandboxed code execution.

- [Website](https://swe-agent.com/) [GitHub](https://github.com/SWE-agent/SWE-agent) [Blogpost](https://swe-agent.com/blog/swe-agent-main-swe-bench)
- Main focus: Multi-purpose agent framework with sandboxed execution
- Useful for: Solving GitHub issues and custom coding tasks

## SWE Fixer

SWE Fixer by InternLM trains 7B and 72B fine-tuned models for localization and coding, using only 2 inferences per issue. This makes it extremely cheap and effective, though you need to somehow host these custom models. It’s very specialized for solving GitHub issues, but most likely the cheapest approach. Great success with only two inferences per issue, WOW. Though I’m not sure if it is easy to replicate or reuse.

- [GitHub](https://github.com/InternLM/SWE-Fixer) [Paper](https://arxiv.org/abs/2501.05040)
- Best score: 32.8% issues solved
- Main focus: Fine-tuned models with minimal inference
- Useful for: Specialized GitHub issue resolution, very cost-effective

## Composio Agent

Composio Agent is built using Composio’s SWEKit framework, which allows for the creation of various specialized software engineering agents. This agent employs a multi-agent architecture to efficiently handle complex software engineering tasks, with specialized agents for different aspects: SWE ENGINEER as the manager, CODE ANALYSIS for in-depth code analysis, and EDITOR for code modification and execution. The system utilizes tools for file editing and reading, Git operations, code indexing, and LSP tools for improved code comprehension.

- [GitHub](https://github.com/ComposioHQ/composio/tree/master/python/swe/agent) [Website](https://composio.dev/) [Article](https://dev.to/composiodev/we-made-an-ai-swe-that-solved-4860-of-issues-on-the-swe-bench-100-open-source-aop)
- [Article](https://dev.to/composiodev/we-made-an-ai-swe-that-solved-4860-of-issues-on-the-swe-bench-100-open-source-aop)
- Best score: 48.60% issues solved
- Main focus: Multi-agent architecture with specialized roles
- Useful for: Complex tasks with comprehensive tooling

## AutoCodeRover

AutoCodeRover is a fully automated approach for resolving GitHub issues where LLMs are combined with analysis and debugging capabilities to prioritize patch locations ultimately leading to a patch. One might use this for both bug fixing and feature addition. This approach is relatively cheap at approximately $0.7 per issue.

- [GitHub](https://github.com/AutoCodeRoverSG/auto-code-rover)
- Best score: 46.20% issues solved
- Main focus: Automated issue resolution with analysis and debugging

## Agentless

Agentless takes a quite interesting approach with three main phases: localization to find fault locations, repair to sample multiple candidate patches, and patch validation to select and validate the best solution. All phases are implemented in a big monofile of about 700 lines. This approach is very cost-effective at $0.34 per issue and achieves impressive results.

- [GitHub](https://github.com/OpenAutoCoder/Agentless) [Paper](https://arxiv.org/abs/2407.01489)
- Best score: 50.80% issues solved
- Main focus: Three-phase approach without traditional agent architecture
- Useful for: An easy approach to study if you want to get started with coding agents

## Moatless-tree-search (SWE-search)

Moatless-tree-search uses Monte Carlo tree search with a custom reward function — a technology that was one of the key approaches to the success of AlphaGo. This is a fascinating approach that explores different solution paths systematically. While probably pretty expensive, it represents an interesting direction for coding agents.

- [GitHub](https://github.com/aorwall/moatless-tree-search) [Paper](https://arxiv.org/pdf/2410.20285)
- Best score: 31% of problems solved
- Main focus: Monte Carlo tree search for systematic exploration

## Moatless tools

Moatless tools is a collection that uses the SWE-bench benchmark to verify ideas. This approach is pretty cheap and offers impressive efficiency. With Claude 3.5 Sonnet, it achieves a 39% solve rate at just $0.14 per issue, while Deepseek V3 reaches 30.7% at an extremely cost-effective $0.01 per issue.

- [GitHub](https://github.com/aorwall/moatless-tools) [Website](https://experiments.moatless.ai/)
- Best score: 39% solve rate with Claude 3.5 Sonnet
- Main focus: Cost-effective solutions with various models

## IDE Integrations

## AIDE

AIDE uses SWE-search rewards but without Monte Carlo search, instead running multiple complete runs. It’s currently the state-of-the-art on SWE-bench verified, resolving 62.2% of the issues. The team scaled their agent on test time inference and re-learned the “bitter lesson” that general methods leveraging computation are ultimately the most effective. While expensive at around $20 per issue, the results are impressive.

- [Website](https://aide.dev/) [Blogpost](https://aide.dev/blog/sota-bitter-lesson)
- Best score: 62.20% issues solved
- Main focus: Scaled inference with reward-based learning
- Useful for: High-performance issue resolution with computational scaling

## Appmap Navie

Appmap Navie is an AI code architect with the context to understand how your app works when it runs, similar to a principal engineer or software architect. It’s available as a VSCode extension and can use GitHub Copilot subscription for LLM usage. Appmap data provides Navie with accurate information about application behavior, APIs, database queries, and more, offering valuable context for more challenging questions.

- [GitHub](https://github.com/getappmap/vscode-appland) [Website](https://appmap.io/)
- Best score: 47.20% issues solved
- Main focus: Runtime analysis and AI-powered code architecture
- Useful for: Understanding application behavior and making context-aware suggestions

## Other Popular Coding IDEs

For completion, I will mention a few popular choices for coding assistants and coding ideas. These are popular choices at the moment. Keep in ming that the quality is not as clear, as they are not benchmarked on SWE bench and it might be difficult to use them as stand-alone agent without regular human input:

- Most popular is Cursor IDE: not open source, not benchmarked — VSCode with GitHub Copilot is also very popular
- Open source alternatives are VSCode extension Cline and its fork RooCode
